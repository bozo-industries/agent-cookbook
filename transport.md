# Shell, SSH, and API Reliability

Use these rules whenever a command crosses a shell, SSH, HTTP, JSON, or encoding boundary:

1. Identify every parser in the path before running the command, such as PowerShell -> native argv -> SSH -> remote shell -> JSON. Minimize the number of parsing layers instead of adding escapes until a command happens to work.
2. In PowerShell, invoke executables with `&` and an argument array. Prefer literal single-quoted strings for fixed text. Never use `Invoke-Expression`, and do not interpolate untrusted or secret values into command strings.
   Windows does not expand wildcard path arguments for `rg`. Search a concrete directory with `-g 'pattern'`, or resolve an exact path using `rg --files`, rather than passing paths such as `scripts/deploy*` to `rg`.
3. Never assume the machine's locale or default text encoding. Use UTF-8 explicitly for files, standard input, standard output, subprocesses, and network payloads. On Windows, enable Python UTF-8 mode with `PYTHONUTF8=1` or `python -X utf8` when a tool does not specify its own encoding; set PowerShell and console encodings deliberately when piping non-ASCII text.
    Python `Path.read_text()` can silently decode UTF-8 web assets as Windows cp1252 and corrupt glyphs when they are written back. Pass `encoding='utf-8'` to both reads and writes. If corruption has occurred, recover the characters from the verified original bytes, then version and revalidate the repaired asset; do not repeatedly reinterpret an already corrupted string.
4. Treat native-program exit codes as authoritative. PowerShell may surface native stderr as error records, while tools such as search, Git, and GitHub CLI may use nonzero codes for expected states such as no matches or a missing repository. Interpret each tool's documented result before classifying it as a failure.
5. Validate shell-specific syntax before combining operations. Do not assume Bash syntax works in PowerShell or vice versa. Keep commands fail-fast and check `$LASTEXITCODE` after important native operations so a later successful command cannot hide an earlier failure.
6. In PowerShell, wrap command or pipeline output in `@(...)` before relying on `.Count`, numeric indexing, or collection comparisons. A single result may otherwise collapse to a scalar, and indexing a string returns a character rather than a path or record.
7. PowerShell statement-style control constructs such as `foreach (...) { ... }` cannot be piped directly. Assign or collect their output first, or wrap the construct in `@(...)` or `$(...)`, before sending it through a pipeline.
8. For SSH, keep the remote command small and fixed. PowerShell OpenSSH commands containing spaces, JSON, pipes, regular expressions, or inline code must use a single-token argument where valid or an exact UTF-8 script encoded as base64 and decoded remotely; do not rely on nested quote escaping. This includes ordinary multiword option values such as deploy reasons: use a delimiter-safe single token when semantics permit, or transport a script when the exact spaces matter. Send secrets and non-ASCII files with a binary-safe file transfer. Base64 is transport encoding, not encryption; never treat it as secret protection.
9. Build JSON with a serializer, not manual quote escaping. Send request bodies from standard input or a temporary file with an API client's binary/file-body option. Use proper URL/query encoders rather than concatenating parameters.
10. Pass secrets through the provider's credential mechanism, protected files, environment variables, or standard input as appropriate. Do not place credentials, tokens, cookies, private keys, or decoded secret payloads in command history, logs, tracked files, or diagnostic output.
    When supplying a secret through standard input, never allocate a PTY: terminal line discipline can echo the input into captured output even when the receiving script does not print it. Use a plain-pipe process/session with echo disabled, and keep all success/failure output sanitized.
11. Before committing in a new worktree, verify repository-local Git identity and remotes. If identity is missing, derive a suitable repository-local identity from the authenticated Git host account when unambiguous; otherwise ask. Do not change global Git identity merely to make one commit succeed.
12. Treat Git-host CLI authentication, HTTPS credentials, and SSH keys as separate transports. A URL-scoped Git credential username can select a different account from the authenticated GitHub CLI and prevent its helper from returning credentials. Check `gh api user --jq .login` and the exact Git credential username configuration, then override the username and helper for that command only; do not switch shared logins or expose tokens. If an `insteadOf` rewrite inserts a different username into the HTTPS URL, a credential-helper override alone is insufficient: use a per-command `url.https://<authenticated-login>@github.com/.insteadOf=https://github.com/` override together with an empty helper followed by `!gh auth git-credential`. Preserve the configured remote and shared authentication. Before an SSH push, verify that the current process can use an authorized key; a logged-in host CLI does not prove SSH access. If SSH is unavailable but the host CLI is authenticated, use its HTTPS credential helper rather than retrying SSH unchanged or exposing a token in a URL or command.
13. Capture the exit code, stderr, and HTTP status before retrying. Treat malformed commands, validation responses, authentication failures, missing tools, locale failures, and quoting/encoding errors as deterministic; fix the cause instead of retrying unchanged.
    For multi-step native producers, persist each completed command's actual exit code and sanitized stdout/stderr before a fail-fast assertion; otherwise a later generic exception loses the failing substage's evidence. If source generation or an earlier validation already succeeded, verify and hash those artifacts, then resume only the unfinished check in a separately named report. Do not regenerate successful geometry merely to obtain diagnostics. Choose a bounded worker memory budget using measured same-runtime needs and headroom while retaining system-reserve and process-tree deadlines. A peak near the enforced memory limit with no reported guard-stop reason is an observation, not proof of the exact native failure cause; reconcile it with the actual command diagnostics before attributing the failure.
14. Retry only genuinely transient failures such as connection resets, timeouts, rate limits, and selected 5xx responses. Use bounded retries with backoff and honor `Retry-After`. Reads may be retried when safe; never blindly retry a write unless it is idempotent, uses an idempotency key, or remote state is checked first.
15. When a cross-boundary command fails, reduce it to the smallest read-only probe and validate each boundary independently: local serialization and encoding, executable availability, transport connectivity, remote interpreter, authentication, then the final operation.
16. Preserve bundled, vendored, and unrelated user files. If a check reports a pre-existing formatting issue in such a file, isolate and report it instead of silently rewriting upstream content or weakening checks for the files being changed.
17. Verify state after remote writes using a separate read. Report the exact layer that failed and preserve useful sanitized diagnostics instead of labeling every failure as transient.
    Before claiming storage durability, inspect the cache-policy semantics and verify the record through the durable query/read path. Memory-only flags can look persistent in an inaccurate mock; keep mocks faithful to the storage contract and test reuse after replacing the storage process's memory cache.
18. Keep Windows PowerShell 5.1 and its older .NET surface in mind. For portable in-memory SHA-256, use `SHA256.Create().ComputeHash(...)` plus `BitConverter.ToString(...)`; newer conveniences such as `SHA256.HashData` and `Convert.ToHexString` may be unavailable.
   The same compatibility constraint applies to path helpers: `System.IO.Path.GetRelativePath()` may be unavailable. For a verified child path, normalize the root with a trailing directory separator, require an ordinal-ignore-case prefix match, then take the substring and normalize separators; do not silently fall back to unchecked string replacement.
19. `gh api -f` supplies request fields and can select a write method unless the method is explicit. For read-only GitHub API queries with fields such as `ref`, pass `-X GET` and verify the returned HTTP status before parsing the body.
20. Do not reuse PowerShell automatic variable names such as `$PID`, `$HOME`, `$Host`, `$Error`, `$Matches`, or `$Input` for task state. In particular, `$Input` can silently retain pipeline-enumerator semantics and make path-length or substring calculations operate on the wrong value. Use task-specific names (`$amazonPid`, `$captureRoot`, `$inputRoot`, `$probeResult`) so assignments cannot fail or clobber shell state.
21. When serializing native-command output, keep PowerShell error records out of the data stream. Some native tools write progress or diagnostics to stderr, which PowerShell can surface as `NativeCommandError`; redirect or suppress expected progress separately, and serialize only controlled stdout/status objects.
22. Windows PowerShell 5.1 writes a UTF-8 BOM with `Set-Content -Encoding utf8`. For JSON, HAR, cURL captures, or other inputs consumed by strict parsers, use the repository writer or `[IO.File]::WriteAllText($path, $text, (New-Object Text.UTF8Encoding($false)))` when a BOM-free UTF-8 file is required.
    When reading an existing CSV, verify its encoding marker before indexing header names. A UTF-8 BOM decoded as plain `utf-8` becomes part of the first header (for example, `\ufeffReference`) and can cause a misleading missing-column error. For a verified UTF-8 source with an optional BOM, use `utf-8-sig` in the scoped reader; preserve and hash the original bytes rather than rewriting the file to accommodate the parser. Include BOM-bearing and BOM-free header fixtures.
23. Do not call string methods on optional native output without a null guard. A missing device line, empty command result, or failed probe can make `.Trim()`, `.Split()`, or indexing throw before the real transport state is reported.
    PowerShell HTTP response `.Content` can be a byte array rather than a string, depending on the response media type. Check its type before calling string methods; decode verified textual metadata with an explicit encoding (for example, UTF-8 for a checksum response), then validate its expected shape. Do not stringify a byte array or assume an HTTP success response is decoded text.
24. Frida and other prompt-toolkit/interactive CLIs on Windows may require a real PTY. If a read-only CLI probe fails with console or prompt-toolkit errors under plain pipes, rerun it with a PTY before changing the target process or transport setup.
25. When a package runner or control CLI prints its invocation before a JSON response, do not parse from the first `{`; echoed JSON arguments may appear there. Prefer a machine-readable or silent mode when available. Otherwise isolate the final response object with a validated delimiter or parse the last complete JSON document, then verify its expected top-level keys before using it.
26. When running Node.js source from standard input in a package that uses ES modules, do not mix CommonJS `require()` with top-level `await`; Node treats that syntax as ambiguous. Use ESM `import` with `--input-type=module`, or keep CommonJS and wrap asynchronous work in an async function or IIFE. To consume piped standard input by numeric file descriptor, use `readFileSync(0, "utf8")` from `node:fs`; current Node releases do not accept fd `0` as a path in `node:fs/promises.readFile()`.
27. In PowerShell, suppress return values from .NET methods that return request or response objects when those objects may contain credentials in headers. Assign the result or cast it to `[void]`; for example, do not leave `HttpResponseMessage.EnsureSuccessStatusCode()` as an unassigned statement because PowerShell will print the full response, including request headers.
28. Windows PowerShell may decode a piped string into records and write native standard input with platform line endings, even after the in-memory text was normalized to LF. When a remote script requires byte-exact LF endings, encode its UTF-8 bytes as base64 locally and decode them into the remote interpreter instead of piping the PowerShell string directly.
    Python text-mode subprocess input on Windows can also translate LF to CRLF. For byte-sensitive local protocols such as a Git patch against LF blobs, pass UTF-8 `bytes` through binary subprocess input rather than `text=True`; validate with `git apply --check` before applying. Do not compensate for a transport newline change by weakening patch-context matching.
29. A shell-command timeout on Windows may terminate only the PowerShell wrapper while leaving native child processes running. For long-lived Java, router, renderer, simulator, or similar jobs, launch with `Start-Process -WindowStyle Hidden -PassThru`, retain the exact returned PID, poll that PID explicitly, and terminate only that verified process if the operation times out or is cancelled. Do not assume a wrapper timeout killed descendants, and do not clean up by broad process-name matching.
30. After cancelling or terminating a yielded command cell, treat wrapper completion as unrelated to descendant cleanup. Before relaunching, inspect the retained child PID and its process tree, verify each target by executable path, command line, parent PID, and start time, then stop only that validated tree and confirm it exited. Parent PIDs can be stale after PID reuse, so exclude any apparent child whose creation time predates the recorded parent launch; a matching `ParentProcessId` alone is never sufficient. Never use a broad process-name kill to compensate for an orphaned child.
31. Windows PowerShell 5.x does not support the PowerShell 7 null-coalescing operator `??`. For scripts that must run on the default Windows host, use `ContainsKey()`, explicit `$null` checks, or conditional assignment instead of `??`, and parse-check with the target PowerShell version before launching long-running work.
32. When checking cookbook freshness in a dirty worktree, compare the committed blob to the upstream blob separately from the working copy. A local working-file hash that differs from upstream may be an intentional uncommitted user change; do not stage, overwrite, or describe it as stale without inspecting both diffs.
33. On Windows, run FreeCAD Python automation with the bundled `bin\\python.exe`, not `FreeCADCmd.exe`, when the script needs ordinary `argparse` options. `FreeCADCmd.exe` consumes unknown switches as application options unless its version-specific pass-through syntax is handled exactly. For a long FreeCAD build, launch or monitor the bundled Python process by exact PID because a shell timeout can leave it running.
34. PowerShell `-LiteralPath` never expands wildcard characters. To copy every child of a directory while retaining literal-path safety, enumerate with `Get-ChildItem -LiteralPath $source` and pass each returned `.FullName` to `Copy-Item -LiteralPath`; then compare an enumerated relative-path/size/hash manifest before relying on the snapshot. Do not combine `-LiteralPath` with `*` and assume files were copied.
35. When loading a Python module manually with `importlib.util.module_from_spec()` and `spec.loader.exec_module()`, register it in `sys.modules[spec.name]` before executing the module body. Decorators such as `@dataclass` may resolve annotations through `sys.modules` during import and fail with a misleading `NoneType.__dict__` error when the registration is omitted.
36. Do not `source` or dot-invoke dotenv/application env files in a shell unless the owning format explicitly guarantees shell syntax. Unquoted spaces, parentheses, hashes, and provider-specific values may be valid to the application's parser but invalid or meaning-changing in Bash or PowerShell. Use the application's normal config loader, a dotenv parser, or a narrow parser that reads only the required key without printing secret values.
37. Catch browser-automation exceptions before printing or serializing them when their messages may include DOM excerpts, request URLs, or element snapshots. Report only a sanitized exception type and a bounded, manually selected summary; Playwright and similar tools can embed short-lived signed URLs, private page text, cookies, or other session material in otherwise routine timeout and actionability diagnostics.
38. In PowerShell, pass Gradle project properties containing dotted names and an equals sign as one explicitly quoted argument, especially instrumentation selectors such as `'.\\gradlew.bat connectedDebugAndroidTest'` arguments of the form `'-Pandroid.testInstrumentationRunnerArguments.class=com.example.Test'`. An unquoted property can be split and interpreted as a Gradle task rather than an option; verify the requested test count in the runner output.
39. Android `adb shell am start` cannot directly launch a manifest activity with `android:exported="false"`, even for local QA. Launch the exported launcher activity and navigate through the app UI, or use an instrumentation process that runs under the application UID; do not weaken production export boundaries merely to automate screenshots.
40. In PowerShell, assign operator expressions such as `-replace`, `-join`, and `-split` to an intermediate variable before passing the result into a .NET method call. Inline comma-bearing operator syntax can be parsed as multiple method arguments and produce misleading overload or argument-count errors; compute the string first, then call the method with that variable. In expandable strings, delimit variable names with braces when punctuation immediately follows them (for example, `"${path}?ref=master"`); otherwise PowerShell can absorb characters such as `?` into the variable name and silently construct the wrong URL.
41. Do not assume a remote Linux host has `jq` installed. Before piping control or API output into it, probe availability; otherwise use an already-present runtime such as Node.js or Python to parse JSON, or inspect the bounded raw response. A missing downstream parser can close the pipe and make an otherwise successful producer report a misleading `EPIPE` failure.
42. In PowerShell, prefer a static .NET constructor such as `[Drawing.Bitmap]::new(1024, 1024, [Drawing.Imaging.PixelFormat]::Format32bppArgb)` when an overload receives an enum. `New-Object TypeName arg1,arg2,[Enum]::Value` can stringify the enum token and fail overload binding; if `New-Object` is required, compute the enum value first and pass it as an actual object.
43. Do not pipe binary native output such as `adb exec-out screencap -p` through PowerShell text pipelines or `Set-Content`; PowerShell can enumerate or decode the bytes and corrupt the file. Write the capture on the device and use `adb pull`, or redirect it through a binary-safe process API, then validate the resulting file before opening it.
44. Before cloning a repository with generated datasets, hash-named assets, or other deep paths into an already-deep Windows workspace, enable Git long-path handling for that operation (`git -c core.longpaths=true clone ...`) or choose a verified short absolute destination. A successful object transfer followed by `fatal: unable to checkout working tree` is not a usable clone; repair the checkout with the same long-path setting before installing dependencies.
45. When invoking installed Chrome or Edge headlessly on Windows while a normal browser session may already be running, pass a task-specific isolated `--user-data-dir` together with `--headless=new`. Without an isolated profile, the launcher can hand the request to the existing browser process, return without producing the requested screenshot or export, and provide no useful failure output; verify the expected artifact after the process exits.
46. In PowerShell, terminate a cmdlet invocation before applying boolean operators to its result. For example, write `if ((Test-Path -LiteralPath $path) -and ((Get-Item -LiteralPath $path).Length -gt 0))`, not `Test-Path -LiteralPath $path -and ...`; otherwise `-and` is parsed as an invalid cmdlet parameter rather than as an operator.
47. PowerShell comparison and regex operators applied to multi-line native-command output operate element by element and return an array. Do not use an expression such as `$installOutput -notmatch 'Success'` directly as a Boolean guard: a mixed Boolean array is truthy even when one line matches. Join bounded, non-secret output before a whole-response regex check, or use an explicit collection predicate such as `Where-Object`, `-contains`, or an `@(...)` count comparison, and still verify the native exit code.
48. Do not launch an npm-generated PowerShell shim with `powershell.exe -File` when downstream CLI options begin with dashes; the shim's argument binding can consume or reject those options before the package receives them. Prefer invoking the package's JavaScript entry point with the exact Node executable, or call a native `.exe` directly with an argument array. Keep global CLI options before the subcommand when the tool's help distinguishes global and subcommand scopes.
49. In a double-quoted PowerShell string, brace a variable when a colon immediately follows its name, for example `"exit code ${LASTEXITCODE}: details"`. Without braces, PowerShell parses the colon as part of a scoped variable reference and rejects the script before execution.
50. When a PowerShell function wraps a native executable, pass dash-prefixed native options through an explicitly named array parameter, for example `Invoke-Tool -Arguments @('-p', 'value')`. Do not rely on a `ValueFromRemainingArguments` parameter for this boundary: PowerShell can bind options such as `-p` as abbreviated function parameters before the native program sees them.
51. For recursive cleanup on Windows, validate every resolved target as a child of the intended root before deletion, then clear read-only attributes on contained files when using `[IO.Directory]::Delete()`. Git pack files and downloaded tool trees commonly retain read-only attributes that make an otherwise correct recursive delete fail partway through. If a partially deleted tree leaves empty directories after a `parameter is incorrect` error, enumerate and verify those exact remaining leaves, delete them from deepest to shallowest, and never replace that diagnosis with a broad process-name kill or an unchecked parent-directory removal.
52. Some execution guards reject a multi-target recursive `Remove-Item` combined with `-Force` even after the paths were validated. Delete each exact validated temporary path with its own `Remove-Item -LiteralPath ... -Recurse` invocation, omit `-Force` unless a confirmed read-only attribute requires it, and revalidate before any forced retry.
53. If an authenticated HTTPS Git push returns 403 while the host API confirms push permission, inspect the remote URL before changing credentials. An embedded username such as `https://user@github.com/owner/repo.git` can select a stale credential even when the active host CLI helper is valid. Retry once with the canonical username-free HTTPS URL, verify the remote write separately, and never expose a token in the URL or command line.
    If a private GitHub smart-HTTP endpoint still returns 403 before issuing an authentication challenge, Git may never invoke an otherwise valid credential helper. Confirm the active `gh` account can read the repository and has push permission, then preauthorize only the single Git command with an in-memory `Authorization` header supplied through temporary `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_0=http.https://github.com/.extraheader`, and `GIT_CONFIG_VALUE_0` environment variables. Derive the Basic value from `gh auth token` in memory, never print it or place it in argv/persistent Git config, and let the task-scoped shell exit immediately after the command. Compare the remote ref before the write and verify it separately afterward.
54. When privileged deployment installs Node dependencies but control commands run as an unprivileged service account, do not assume npm development-tool shims under `node_modules/.bin` are executable across that boundary. Prefer a compiled JavaScript entry point invoked with `node`, or explicitly validate traversal and execute permissions before relying on a package-runner shim.
55. On Windows, do not pass opaque JSON or multiword control arguments through `cmd.exe /c` merely to launch an npm `.cmd` shim. Backslash-escaped quotes are not a reliable `cmd.exe` argument boundary and can truncate JSON or split values. When the target has a compiled JavaScript entry point, invoke it directly with the exact Node executable and an argv array; reserve the `cmd.exe` wrapper for package scripts that genuinely require the `.cmd` shim.
56. When reporting metadata for an opaque or signed URL, do not preserve path segments by position (for example, "keep the first four segments"). Dates, account-scoped directories, UUIDs, receipt ids, and other private identifiers can appear anywhere in the path. Allowlist only exact public route literals that are already safe to report; replace every other non-empty segment with a semantic placeholder, emit query-key names without values, and scan the final metadata for date, UUID, signature, token, and identifier patterns before printing it.
57. Order `apply_patch` update hunks for each file from top to bottom. Its context search advances through the file; a later hunk targeting earlier lines can report missing context even when that text exists. Reorder the hunks or split the edit into separate calls before assuming the file changed or rebuilding its contents. Use one file operation per path in a patch: do not combine Delete and Add for the same path. Prefer an Update operation for replacement, or separate calls when replacing an agent-owned draft, and verify the final file exists.
58. When polling a log that a live Windows process is writing through redirected stdout, open a read-only `FileStream` with `FileShare.ReadWrite` and dispose its reader after each bounded read. `File.ReadAllText()` can fail with a sharing violation even though the log and producer are healthy. Treat that as a reader failure, not proof the producer stopped; retain and verify the exact process handle before retrying or cleaning up.
59. A streaming collector's process start is not subscription readiness. Before launching a measured workload, emit a unique harmless marker and confirm that exact marker in the collector's output with a bounded handshake. A tail-from-latest collector can otherwise miss the initial marker and leave a readiness-gated workload idle. Keep workload/session identifiers distinct from old records, and classify a missing handshake as setup failure rather than missing application behavior. Likewise, confirm the final workload marker in collected output before terminating the collector; successful marker submission does not prove it was flushed to the trace. Reject an incomplete boundary instead of inventing an end time.
60. When selectively staging generated diff hunks, prefer context-bearing patches. Removing earlier hunks from a zero-context diff leaves later new-file line coordinates invalid; `git apply --cached --unidiff-zero --check` can still succeed while inserting code at the wrong location. If zero-context filtering is unavoidable, recompute each new-file coordinate from its old-file position and the cumulative line delta of only the retained hunks. Inspect the resulting staged file, not merely the patch or exit status, before committing; working-tree tests do not validate a different staged snapshot.
61. `adb shell am instrument` can exit with shell status zero and `INSTRUMENTATION_CODE: -1` even when JUnit assertions failed. Require the terminal JUnit `OK (N tests)` summary with the expected test count and reject `FAILURES!!!`, failed status records, or skipped-only runs. Keep the native exit check too, but never use it as the sole instrumentation-success gate; a successful APK reinstall afterward does not validate the preceding test.
62. Before reusing a task-local Python dependency directory, match its native extension ABI to the exact interpreter. A directory containing `cp312` NumPy/OpenCV extensions cannot be loaded by Python 3.13 merely by adding it to `PYTHONPATH`. Inspect the extension suffix and interpreter version, use a matching existing runtime/dependency pair, and validate a minimal import before launching analysis. Do not reinstall or replace a working dependency tree to compensate for selecting the wrong interpreter.
63. Do not limit a native producer's live output with `Select-Object -First`: PowerShell can close the pipeline before the producer finishes, leaving a missing exit status or causing a broken-pipe/invalid-argument write failure. Capture the complete output, redirect it to an appropriate file, or consume it with `Out-Null` when unneeded; check terminal status before inspecting a bounded excerpt or generated artifact. A partially consumed stdout stream is not a successful analysis run.
64. Resolve both the candidate path and its allowed root before checking filesystem containment. A deployment data directory may be a symlink into a separate state volume; comparing a resolved candidate against an unresolved root can reject a valid path. In Python, compare `candidate.resolve().is_relative_to(root.resolve())`; retain the containment check rather than bypassing it after a mismatch, and verify ownership before mutating the resolved target.
65. Recursive ownership or permission repair must not follow symlinks out of the intended directory. Runtime homes can contain executable shims pointing into an installed package; `chmod` on those links can remove execute permission from the real binary. Detect symlinks first, use non-following ownership operations where needed, validate containment for regular entries, and preserve required execute bits. Verify the resulting runtime as its actual service account, not only as root.
66. Node inspector evaluation contexts may not support dynamic `import()`. Never schedule an unhandled dynamic import or other unchecked asynchronous cleanup inside the inspected process: its rejection can terminate the application. On supported Node versions, use `process.getBuiltinModule()` for built-in diagnostics, catch every evaluated asynchronous failure, and verify process health after detaching. Preserve any pre-existing inspector listener; close only a diagnostic listener you opened, using a synchronous built-in reference captured before scheduling cleanup.
67. Check `$LASTEXITCODE` only after a native executable or a script with an explicit exit-code contract. A successful PowerShell script can leave a previous native failure in `$LASTEXITCODE`; use terminating exceptions and capture `$?` immediately after ordinary PowerShell script calls instead.
68. When verifying an exported Git source snapshot on Windows, compare its `git hash-object --path=<repository-relative-path>` result with the staged blob ID so repository line-ending filters are applied consistently; raw file hashes can differ solely because of CRLF conversion. Do not ignore a mismatch without establishing its cause.
69. An HTTP API can accept a browser or PowerShell client while rejecting a library's default User-Agent with 403. Compare the smallest authorized read across clients, capture status and challenge indicators, and test an explicit descriptive application User-Agent before treating the failure as credentials, DNS, or TLS. Keep certificate verification enabled and do not bypass an authentication challenge or CAPTCHA. Never retry the unchanged 403 as a transient failure.
70. `Invoke-WebRequest.Content` can be a byte array when the response lacks a recognized text content type. Check its type before parsing or passing it to a text writer: decode byte content with the response's declared charset, or an explicitly known source encoding such as UTF-8; otherwise retain the bytes with a binary writer. Implicit conversion to a string can silently produce space-separated byte numbers while reporting HTTP success. Verify the decoded format before searching it or relying on a saved artifact.
71. Windows `tar.exe` may require an external `xz` program to read `.tar.xz` archives. If the installed archive reader reports that its filter cannot start, use an existing Python runtime's `tarfile.open(path, 'r:xz')` and inspect selected members with `extractfile()` rather than installing a new tool or executing archive contents. Prefer member reads over extraction; if extraction is necessary, validate member paths and link targets against the intended directory first.
72. Shell automation must propagate failures from every stage. Prefer direct executable/argv calls and verified decoding over pipelines such as `printf ... | base64 -d | sh`, whose decoder failure can be hidden by an empty successful shell. When Bash is required, invoke it explicitly with `-Eeuo pipefail` or set equivalent strict options at the start; do not assume `/bin/sh` supports pipefail. Handle expected nonzero diagnostic results explicitly and report their status rather than suppressing all failures with `|| true`. Validate failure propagation with a failing producer and a successful consumer before enabling mutation or unattended execution.
73. PowerShell does not expand wildcard path arguments for native executables such as `rg`. Use explicit file paths, let the tool interpret its own glob option (for example `rg -g 'vault-*.py' outputs`), or enumerate paths with PowerShell before passing an argv array. Do not pass a literal `outputs/vault-*.py` and assume the shell expands it; distinguish a no-match exit from an invalid-path error.
74. Offline Windows tests of Linux-only filesystem code must model platform-specific APIs explicitly. Constants such as `os.O_NOFOLLOW` and functions such as `os.geteuid` may be absent. Patch them only within isolated test fixtures, and state which kernel protections the fixture cannot exercise. Never add a permissive production fallback such as `getattr(os, 'O_NOFOLLOW', 0)` to make cross-platform tests pass; validate the real protection on the target platform before relying on it for mutation.
75. Structured remote execution can report transport success while a nested guest command failed. Check both layers and preserve a bounded, sanitized failure label from the nested result before replacing it with a generic error. If execution is still unobserved, retain the known process ID and inspect that same handle; an observation failure is not evidence that a write did not occur and must never trigger a blind retry. Verify this behavior with a successful transport carrying a failed guest result and with an unfinished result carrying a process ID.
76. Read and write controlled UTF-8 text artifacts with an explicit encoding, such as `Path.read_text(encoding='utf-8')`. Windows can otherwise use a legacy code page, causing errors or corrupting Unicode punctuation in scripts and instructions. For externally supplied text, use its declared or verified encoding rather than guessing; never silently ignore decoding errors.
77. Verify the exact API endpoint's parameter schema before using filters; similarly named cluster and node endpoints may accept different options. Test fixtures should reject unsupported endpoint parameters rather than silently accepting any request. For Proxmox active backup checks, use the node task endpoint with `source=active` and the appropriate type filter; the cluster task endpoint does not accept `source`. Preserve a bounded operation phase and a controlled failure label so an invalid read can be diagnosed without exporting raw responses or secrets.
78. Git-bundled MSYS executables can interpret Windows drive/backslash paths as relative Unix paths even when invoked directly from Python or PowerShell. Test a genuinely held and released lock before using that distinction to permit installation.

147. Compare scheduler hooks by their own identity during application upgrades. A cron symlink can retain its path, link target, owner and permissions while the linked updater program changes legitimately. Use `lstat` and the link target for symlinks, and hash regular wrapper files; verify timer enablement separately. Persist the before and after identities and exact listener sets before asserting invariants so a failed upgrade can be diagnosed after rollback without replaying it solely to recover missing evidence.

148. PowerShell does not expand wildcard paths passed as native command arguments in the same way as a Unix shell. For ripgrep, pass a verified directory and use `--glob` or `-g` to select filenames instead of positional paths such as `folder/*.py`; those can reach rg as literal filenames and fail before any search occurs. Use explicit resolved paths for operations that require individual files, preserve structured result records, and distinguish an invalid search path from a genuine no-match result.

149. An isolated build environment needs an explicit executable and permission check under the intended application account. Invoke privileged Linux helpers such as `runuser` by their verified absolute paths; do not search a build-user-writable CLI directory for root helpers or assume `/usr/sbin` survives a restricted PATH. A runtime extracted with a private umask can pass a root version check while its directories prevent the service account from executing it. Verify the public runtime's archive-bound contents and ownership, set its intended read/execute permissions, and run a version/import smoke check as the service account before cloning, installing or building. After a pre-build failure, reconcile and reuse verified artifacts in a distinct recorded attempt rather than redownloading or overwriting an active stage.
