# Native FreeCAD Automation

Use this guide for FreeCAD Python modeling, geometric verification, and manufacturing exports. General process, encoding, transport, and Git rules remain in [transport.md](./transport.md) and [commit.md](./commit.md).

## Runtime and source preservation

- Read the project's declared toolchain and use the installed FreeCAD bundled Python for scripts with ordinary command-line arguments. Import `FreeCAD` before `Part` so native paths are initialized. Keep source loading and mutation behind a guarded entry point.
- For focused work, load a hash-bound saved document and copy its shapes. Build in a new document and fresh contained staging directory. Preserve the authoritative document and old release files until the complete replacement has passed its gates.
- Save document and object identifiers as plain strings before closing a native document. FreeCAD Python object wrappers become invalid after `App.closeDocument()`; even reading an old feature's `Name` can raise `ReferenceError`. Reopen the saved file and resolve a fresh object through the retained identifier. Record and hash a completed save before downstream verification so an adapter failure can resume from that exact file without repeating geometric construction.
- Retain the actual `Name` returned by `addObject()`, not merely the requested identifier. FreeCAD normalizes characters such as hyphens and can renumber a colliding suffix; a dictionary keyed by requested names can therefore fail an otherwise successful saved inventory. Require a one-to-one requested-to-actual mapping and verify complete reopened inventory and geometry through that mapping. Include normalization and collision fixtures, and resume from the hash-bound completed native save rather than rerunning geometry to fix a name adapter.
- Keep exact producer/source hashes, parameters, native-tool version, and output hashes. Recheck inputs before publishing. A successful save or native process exit is not geometric verification.
- Distinguish serialized-file provenance from a shape's re-exported BREP payload identity. A native document round-trip can add identity locations or regenerate pcurve records without changing physical geometry. Preserve any raw-payload mismatch as diagnostic evidence; do not ignore it or weaken file-hash bindings. Independently require saved validity and complete inventory, compare surface/curve coefficients, trim ranges, vertices and design properties, and check bidirectional differences only between qualified shapes before accepting geometric equivalence.
- Do not interchange native shape and mesh method signatures. In the bundled FreeCAD 1.1 Python API, use `shape.translate(App.Vector(dx, dy, dz))` but `mesh.translate(dx, dy, dz)`. For a rigid print orientation, copy the source mesh and apply a placement matrix so its original triangle topology is preserved; independently compare the serialized coordinates and indices against the declared transform.
- Convert native mesh-point proxies to vectors explicitly with `App.Vector(point.x, point.y, point.z)`. A `MeshPoint` can expose coordinates without supporting the sequence constructor `App.Vector(point)`. Verify the conversion on one point before a long geometry audit; do not repeat completed native Boolean stages merely to diagnose a point-conversion failure.
- Check the installed native method's argument types and codec explicitly. In bundled FreeCAD 1.1, use positional `shape.copy(True, False)` for a geometry copy without mesh data, and pass `Part.Face`, `Part.Edge`, or `Part.Vertex` classes to `getTolerance`, not their string names. Use `importBinary()` for `exportBinary()` artifacts; a generic `read()` call can reject an arbitrary binary-BREP extension. Resume from a hash-bound successful native artifact after correcting an adapter error rather than repeating completed construction.
- In matching PythonOCC 7.8.1 bindings, do not transfer the four-argument `Geom_BSplineCurve.InsertKnot` signature to `Geom2d_BSplineCurve.InsertKnot(U, M, Tol)`: the latter takes three arguments, and internal multiplicity increments are limited by degree. Verify refinement against the installed API and the actual coefficient net. A null pcurve from `BRep_Tool.CurveOnSurface` can appear as a range-only tuple; classify it explicitly as missing/incomplete before constructing a checker, never as zero residual or a passed geometry check.

## Boolean and local-clearance operations

- A whole-solid offset on a complex Boolean result can fail with a closed-boundary error even when the input BRep is valid. Treat that as a deterministic geometry failure; do not retry the unchanged operation or return the input shape as a successful result.
- Preserve terminal failure evidence for the installed runtime's actual kernel exception types. In bundled FreeCAD 1.1, `FreeCAD.Base.CADKernelError` can be distinct from `Part.OCCError`; handling only the latter can leave a failed operation recorded as started. Verify the exception classes, record the specific terminal failure without retrying the geometry, and test the error handler with a synthetic exception before the next expensive operation.
- For a local interface relief, prefer an explicit bounded cutter or a native feature whose extent and clearance can be verified directly. Measure resulting validity, solid count, intersections, receiver material and wall/fillet geometry. Do not substitute the intended clearance value for measuring the actual result.
- A disjoint Boolean intersection can be a non-null empty Compound. In bundled FreeCAD 1.1, `check(True)` on that empty inventory raises a bare BOP error even though no material intersects. Classify zero vertices, edges, faces and solids explicitly before detailed intersection checks; retain the empty result as evidence. Run detailed checks on every nonempty result and on the original manufacturing solids. Verify this distinction with disjoint-box and positive-volume fixtures; do not treat every checker exception as empty or suppress real geometry failures.
- Native plane dimensions follow the plane's local axes, not necessarily positive world axes. Before sectioning or cutting, check the generated plane's actual bounds cover the intended target; a correctly specified normal and large dimensions alone do not prove coverage. Keep a coverage assertion in the probe so a misplaced plane cannot be mistaken for a missing body section.
- Avoid zero-thickness and exactly tangent intersections. For example, a circular clearance hole tangent to a relieved roof can produce a non-manifold triangle edge while the native solid still reports valid and closed. Introduce deliberate finite clearance or an intentionally open groove, without creating an unprintably thin roof. Verify feature and wall dimensions against the actual process.

## Native and exchange-file verification

- Ordinary `isValid()` and closure checks do not include every Boolean-operation suitability check. Run `shape.check(True)` on manufacturing-bound native and reopened exchange solids, and retain any detailed C0 or invalid-curve-on-surface errors as failures even when ordinary validity passes. When exchange fails, compare detailed checks along the source construction lineage to locate the first defective operation before trying serialization variants. Fix the original construction in isolated staging; do not loosen tolerances, omit faces, or treat valid-but-open exchange geometry as a repair.
- For complete-product view names, derive front/rear/left/right from the project's declared coordinate system rather than a projection library's default. Include the viewing-axis direction and check a recognizable feature, such as the entrance, against the label before publication; a conventional component primary view need not be the product's front.
- Check both the native BRep and the serialized STL topology. Count boundary and non-manifold edges when a mesh fails. Do not assume finer tessellation can repair a geometric knife edge, or use a mesh splitter that silently fills holes as evidence of original closure.
- For a pure plane reflection, prefer the native `shape.mirror(base, normal)` operation and qualify the result with detailed validity and exact material comparison. A reflection passed through `transformGeometry()` can unnecessarily convert analytic surfaces to spline geometry and introduce C0 errors even when ordinary validity passes. Preserve that failed conversion, verify an analytic fixture and the actual source, and do not treat the converter failure as a defect in unchanged original manufacturing solids. Export distinct mirrored parts when an asymmetric hole pattern prevents simple translation equivalence.
- A valid closed wire does not prove that its filled planar face or cavity region is valid. Reconstruct and check that region before relying on its area, lofting a cavity, or exporting it as a surface. Non-solid STEP exports can also produce a syntactically valid file with no geometry; independently reopen it and require non-null geometry and the expected entity inventory. Preserve and reject empty exports rather than reporting success from the writer's return code.
- In FreeCAD, `Part.__sortEdges__()` returns one flat connected edge list and can stop before consuming all input edges. Use `Part.sortEdges()` when checking the complete contour inventory: it returns all connected groups. Require the expected group count and equality between total sorted and input edge counts before constructing wires, then verify closure and face validity. Test a disconnected-contour fixture so an API return-shape mismatch cannot masquerade as malformed supplier geometry or silently omit another contour.
- Native bounding boxes can include untrimmed supporting-surface extrema. Use trimmed-face intersections, exact sections, or bounded tessellation to establish physical extents; report any difference rather than silently relaxing a size limit.
- Tessellation can attach a triangulation cache that changes subsequent `BoundBox` results to sampled extrema. Capture the mesh-free BRep bounds with `shape.copy(True, False).BoundBox` before tessellation when checking an analytic datum, and keep sampled bounds explicitly separate. Verify this behavior with a cylinder fixture; do not relax a ground-height or pose tolerance merely because a cached polygon misses a circular extreme.
- Default mass properties can be under-integrated on complex parameterized spline faces. If closed native geometry and a verified mesh disagree in volume, keep the failure and investigate geometry, tessellation and numerical integration independently. Require a scoped, convergence-checked native-surface integral or equivalent validated property calculation before claiming agreement; never relax the threshold or substitute mesh volume as native ground truth. A limited nearest-triangle candidate search likewise provides only an upper distance bound: a failed bound is inconclusive, not proof of actual deviation, and large or elongated triangles must not be overlooked merely because their centroids are distant.
  Before implementing a manual integral or installing another kernel, probe the exact bundled runtime for matching `OCC` bindings after importing `FreeCAD`. Where available, `brepgprop.VolumePropertiesGK` supports adaptive native-surface integration with explicit relative accuracy, `OnlyClosed=True`, and `IsUseSpan=True` for B-spline knot spans. Reject negative error estimates, verify analytic straight and curved fixtures, and compare successive tighter accuracies before accepting partition or hollow-volume agreement. Bind every imported BREP and preserve its original default-property discrepancy. This is not mesh integration, a geometry repair, or permission to change tolerances.
  Do not treat knot-span handling as universally more accurate. After Boolean trimming, a span-enabled calculation can converge and report a small error while still failing native whole-versus-halves conservation. Probe both `IsUseSpan` settings on the unchanged BREP files; require analytic fixtures, accuracy convergence and native partition or hollow-volume invariants for the selected mode. Preserve the failing mode and its discrepancy as diagnostic evidence. Select a mode only within its verified geometry scope, never because its value happens to match the mesh, and keep the original agreement thresholds unchanged.
- A valid BRep can contain zero-length degenerate edges whose `Curve` accessor raises an undefined-curve error. When locating a known nonzero feature such as a circular boss root, exclude zero-length edges before typed curve inspection and still require the expected feature count and dimensions. Do not blanket-catch errors on nondegenerate candidates or treat an incomplete feature search as success. Keep native validity and independent mesh checks as separate gates.
- One geometric contour or blend can be partitioned into several native edges or faces by previous Boolean intersections. Verify complete contours rather than assuming one record per feature: require consistent circle identity, gap-free non-overlapping parameter coverage and total arc length. For a split analytic blend, independently check radii, placement and aggregate trimmed area. A changed record count alone is neither a missing feature nor permission to weaken the geometric requirement.
- Reopen STEP and saved native files independently. Check valid closed solids, symmetric-difference volume, units and dimensions. Load STL through an independent reader without automatic hole repair; verify closure, winding, envelope and volume error.
- Direct STEP export can silently omit native offset-curve extrusion faces and return a valid but open partial shape. Require the expected solid, shell and face inventory as well as validity and closure. A copied shape converted with `toNurbs()` may provide a supported exchange representation, but publish it only after independent native/conversion/STEP geometry and inventory checks in new staging files. Preserve the analytic native mother for radius and wall measurements; conversion is not permission to repair missing geometry or relax dimensional gates.
- Hardware envelope proxies must be labeled as proxies. A smooth nominal screw or insert is not a manufacturer thread/knurl model or a qualified tolerance stack.
- Distinguish designed cold heat-set interference from an unintended collision. A nominal insert envelope can intentionally overlap the smaller printed pilot. Classify only the exact approved insert/receiver pair, independently verify the expected annular material and full axial extent, and keep all other interference gates strict. For an unchanged inherited joint, compare its original and modified intersections with bidirectional material differences as well as dimensions and volume; equal volume alone does not prove unchanged fit. This classification is not physical heat-setting, tolerance, load or service approval.

## Native projection and drawing artifacts

- `TechDraw.projectToSVG()` returns a fragment that may contain several sibling groups. Wrap it in an SVG document before whole-document XML validation, and give unreferenced path IDs unique names when composing views. Save and hash expensive completed native projection output before downstream parsing or layout work so an adapter failure does not force a geometry rerun.
- A syntactically valid SVG or successful raster export does not prove readable text. Offscreen Qt can start with no system fonts; register a verified local font, require the necessary glyphs, and inspect the actual raster. Check dimension arrows too, since renderer support for SVG marker features differs; explicit annotation polygons can avoid that dependency without changing projected geometry.
- Preserve physical drawing scale across formats. For a raster generated at eight pixels per millimetre, set and independently reopen its resolution metadata at 8000 dots per metre. A pixel size alone does not establish an A4 sheet or a 1:1 print scale. Keep nominal reference drawings clearly separate from manufacturing approval.

## Assembly and service evidence

- Model the actual installation and removal sequence, not only final poses. Include the complete key/driver body, socket engagement, approach, withdrawal, turning/reindexing space and relevant neighboring parts.
- Discrete collision-free samples establish only the sampled poses. For a continuous motion claim, use a conservative swept envelope, an analytic separation bound, or an equivalent coverage argument; retain the scope and assumptions with the result.
- Verify complete rigid placement frames on both sides of a mirrored assembly. Reversing one axle rotation can also invert its mounting platform. Require the actual bearing-face height, normal, interface coordinates and installed wheel-ground datums, and include a deliberately inverted-side fixture. Correct a metadata-only pose error with an explicit checked addendum bound to the unchanged native source; do not quietly regenerate or rewrite the previous source evidence.
- Check the purchased board or module envelope as well as its printed cassette. A narrower printed carrier does not bound the wider board it contains.
- A regularized Boolean common of two solids can omit their shared bearing face entirely. Distinguish material overlap from designed surface contact: independently intersect the native bearing faces, require the expected complete area and geometry, and verify zero separation. An empty solid common is not proof that a bearing is absent or that a required clearance exists. Test touching and deliberately separated boxes before using a contact classifier; keep intentional seated contact separate from collision-free clearance claims.
- For through-hole assemblies, include the untrimmed contact tails, solder/pigtail process allowance, underside insulation and fastener/support stack, not only the flat PCB box. Distinguish board-top, board-underside, component seating-flange and table/floor datums. Read the actual dimensioned manufacturer drawing and tolerance notes before deriving heights. A retained contact-compression value couples PCB height, free-tip height, mating plane and the supported assembly pose; do not move one independently or assume tail trimming is an approved fix.
- Keep digital joint candidates separate from whole-assembly approval. Retain physical coupon, torque, tolerance, load, drop, service-cycle and safety gates. Explicitly state required power isolation, empty assembly state, and whether service requires lifting the unit off its supporting surface.
